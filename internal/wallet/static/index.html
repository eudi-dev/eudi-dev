How to use this wallet

Test issuance with OpenID4VCI and presentations with OpenID4VP. This wallet supports SD-JWT VC, mdoc, holder binding, status lists and trusted lists.

Send a credential offer (OpenID4VCI)
/credential-offer?credential_offer_uri=…
Send an authorization request (OpenID4VP)
/authorize?client_id=…&request_uri=…
PID trusted list for your verifier
/api/trustlist

To open a custom-scheme link in a browser, replace everything before the ? with the matching endpoint URL. Keep the query parameters.

Open a custom-scheme link from the CLI (any platform)
eudi wallet accept 'openid4vp://authorize?client_id=…'
Register the wallet as URL handler (macOS and Linux)
eudi wallet register

After wallet register, the system opens openid4vp://, eudi-openid4vp://, haip-vp://, eu-eaap://, openid-credential-offer://, haip-vci:// and eu-eaa-offer:// links in this wallet. See the wallet documentation for all endpoints.

Try the demo issuer or demo verifier.

Register your verifier or issuer with the wallet's registrar. You get an access certificate and a registration certificate. With --arf the wallet checks both, as the ARF requires.

1. Register the relying party
POST /api/registrar/wrp
2. Get an access certificate for your key (send a CSR)
POST /api/registrar/access-certificates
3. Get a registration certificate (verifier_info or issuer_info)
POST /api/registrar/registration-certificates

4. A verifier signs its request object with the access certificate's key, puts the chain in x5c and adds verifier_info. An issuer signs its metadata the same way and adds issuer_info.

With the CLI
eudi registrar verifiers add --name "Example Shop" --purpose "Age check" --dcql query.json
eudi registrar issuers add --name "Example University" --attestation dc+sd-jwt:urn:example:diploma:1

Registrar walkthrough

Test a verifier page that uses the W3C Digital Credentials API. The eudi-dev browser extension answers navigator.credentials.get() with this wallet instead of a phone wallet. It works in Chrome, Chromium, Edge and Brave.

Install from the Chrome Web Store

The store version uses the public demo at https://eudi-test.dev. To use this wallet, set as the wallet in its popup.

Other ways to install
Open a browser with the extension loaded (macOS and Linux)
eudi wallet browser --wallet-url

To use the extension in your everyday browser profile, download it and unzip it. Open chrome://extensions, turn on Developer mode, choose Load unpacked and select the folder. It uses this wallet. You can set another wallet in the extension popup.

Try it on the demo verifier: choose Digital Credentials API under Delivery.

Certificates

Revoke adds a certificate to its CRL. Withdraw removes it from the trusted lists of this wallet. Verifiers that check the CRL or the trusted lists then reject this credential.

Trust & certificates
Trusted lists

Trusted lists signed by this wallet (ETSI TS 119 602). The list of trusted lists links to all of them.

Certificates & keys
Trust anchor
PEM JWKS Trust this CA. Credentials and wallet attestations carry only their signing certificates, and those can change.
Signing key
JWKS Signs credentials, wallet attestations and key attestations.
Registrar
PEM JWKS CA Signs registration certificates, their status list and registrar responses. Its CA is on the registrar list.
Relying party access CA
PEM JWKS Signs the access certificates of registered relying parties. It is on the access-ca list.
TLS
PEM JWKS Wallet HTTPS certificate for certificate pinning.
Add a provider CA

For your own issuer, verifier or registrar. The wallet adds the CA to one of its lists.

Add an external list

Use a trusted list published by someone else, such as a national list of PID providers. The wallet accepts it only if it trusts the CA that signed the list.
